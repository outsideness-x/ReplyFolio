# Как устроен GrowthThread

## Вход и доступ

Browser → same-origin Pages Function → HMAC-подписанный Supabase Edge endpoint → приватная PostgreSQL сессия → Supabase Auth.

Turnstile и лимиты защищают запрос email-кода. До проверки кода ответ одинаков для команды и посетителей. Приватное приглашение привязывается к подтверждённому email и конкретному Auth user ID; домены и произвольные metadata не дают права входа. Команда проходит TOTP MFA. Проверенный фактор закрепляется за приглашением. Email без MFA не открывает данные.

Браузер хранит непрозрачную HttpOnly Secure cookie; access/refresh tokens зашифрованы в private schema. Сессия ограничена 12 часами и 30 минутами без backend-запросов, не более трёх сессий на пользователя. Видимый кабинет опрашивает сервер, поэтому это тайм-аут отсутствия запросов, а не движения мыши.

Pages подписывает метод, маршрут, query, тело, cookie, IP, user agent, время и одноразовый nonce. POST требует совпадающий Origin. Edge проверяет подпись, срок и повтор nonce. Запрос с произвольным bearer JWT не заменяет этот путь.

Все browser grants к таблицам и служебным RPC отозваны. RLS дополнительно требует команду, членство, AAL2, активную утверждённую сессию и совпадение подписанного Auth session_id. Service-role endpoints самостоятельно проверяют workspace и IDs; чужой UUID не даёт доступа. Изменение подключения Instagram требует роли owner и свежего MFA.

## Сообщения

Instagram → подписанный webhook → приватная очередь PostgreSQL → worker → сценарий → очередь отправок → Instagram Send API.

Webhook проверяет HMAC-SHA256 исходных байтов и сохраняет batch одной транзакцией до подтверждения. Дедупликация, lease и блокировка диалога защищают от повторной обработки. Cron восстанавливает отложенные и прерванные задачи.

shared/engine.ts общий для сервера и симулятора: сообщения, материалы, кнопки, контакты, условия, теги, заявки, ожидания и менеджер. Активный диалог хранит копию сценария. Отключение/удаление сценария останавливает продолжение.

Перед отправкой проверяются подключение, режим диалога и окно ответа. До внешнего запроса статус становится uncertain; неоднозначный сетевой результат не повторяется автоматически. Явный 429 откладывается. Exactly-once доставка внешней платформой не гарантируется.

Ответ менеджера переводит диалог в human, удаляет активную сессию и отменяет подготовленные сообщения бота через mode_revision. Ответ из Instagram обнаруживается через echo.

## Хранение

Public schema содержит бизнес-данные, но название схемы не означает публичный доступ. Private schema: приглашения, waitlist, server sessions, зашифрованные токены, OAuth states, audit, очереди и блокировки. Она не экспонируется через PostgREST.

Instagram токены и Auth токены используют разные AES-GCM ключи и привязку к ID. OAuth state одноразовый, до 10 минут, связан с браузером, пользовательской сессией и текущими правами владельца. Изменение роли или доверенного фактора прекращает ожидающий OAuth.

Storage материалов публичный, чтобы ученики открывали PDF. Загрузка выдаётся через API на один случайный путь своего workspace; прямые пользовательские upload/delete policies закрыты. Загружать следует только публичные материалы.

## Развёртывание

React/TypeScript/Vite, Cloudflare Pages Functions шлюз, шесть Supabase Edge Functions, девять SQL-миграций и Cron/Vault. В browser bundle нет Supabase Auth client, JWT, серверных ключей или приглашённых email.

По умолчанию отображается landing с email-входом. DEV demo включается явно через ?demo=1; production demo выключено. LocalRepository содержит вымышленные данные, SupabaseRepository обращается к same-origin API и опрашивает данные раз в 15 секунд, пока вкладка видима.

## Подготовленные разделы аналитики

Аналитика приложения, Instagram и взаимосвязи доступны внутри того же закрытого кабинета и через ⌘K. Пока это статические экраны: нет SDK событий, ingest API, таблиц аналитики, фоновой загрузки Insights, фильтров или расчётов. Прочерки обозначают отсутствие данных, а не нулевые значения. Backend Direct не меняется.

Будущее подключение Instagram Insights требует отдельного instagram_business_manage_insights для Instagram Login. Это разрешение сейчас не запрашивается. Официальный API поддерживает статистику собственных профессиональных Business/Creator аккаунтов и их контента; доступность метрик и истории ограничена Meta. [Instagram Insights](https://developers.facebook.com/documentation/instagram-platform/insights).

Экран взаимосвязей предусматривает сопоставление агрегированной динамики. Для атрибуции кампаний к событиям приложения позднее понадобятся размеченные ссылки и события; совпадение дат само по себе не устанавливает причинность или личность пользователя.

## Проверки и границы

48 unit/integration тестов и 18 Chromium проверок: движок, webhook batch, очереди, PostgreSQL RLS и закрытые grants, приглашения, session binding, MFA factor pinning, OAuth, CSRF, подписи, waitlist, навигация и 390/768/1440px. TypeScript/build и Deno проверяют исходники. Privacy scan проверяет файлы, историю Git и build.

Браузерные тесты входа подменяют ответы API; PostgreSQL проверки выполняют настоящие SQL-функции в PGlite. Они не заменяют живой Supabase Auth, email, Turnstile, Storage, Cron/pg_net и Meta. Эти сервисы ещё не подключены; реальная доставка и cloud-конфигурация не подтверждены.

Первая версия для одного бизнеса: без SaaS billing, AI, рассылок, HUMAN_AGENT, Live comments, галереи публикаций и PDF-вложений. В кабинете доступны последние 1000 сообщений и 100 запусков; более ранние остаются в базе.
