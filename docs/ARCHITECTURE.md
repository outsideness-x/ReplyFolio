# Как устроен ReplyFolio

## Поток сообщения

Instagram → instagram-webhook → приватная очередь PostgreSQL → automation-worker → сценарий → приватная очередь отправок → Instagram Send API.

Webhook проверяет HMAC-SHA256 исходных байтов, записывает пакет событий одной транзакцией и только затем подтверждает его. Один event key не создаёт несколько задач. Worker обрабатывает до 20 задач за вызов и использует lease и блокировку диалога. Cron восстанавливает обработку при сбое или отложенном действии.

Движок в shared/engine.ts общий для сервера и локального симулятора. Он поддерживает сообщения/ссылки, кнопки ответа, сбор имени/email/телефона, условия, ожидание, теги, заявки, передачу менеджеру и завершение. Определение сценария копируется в активную сессию: редактирование не меняет шаги начатого диалога. Выключение или удаление сценария останавливает его продолжение.

Перед каждым исходящим запросом сервер проверяет подключение аккаунта, режим диалога и разрешённое окно ответа. Перед внешней отправкой статус сообщения становится uncertain. При потере ответа сети запрос автоматически не повторяется: интерфейс предлагает проверить Direct. Это снижает вероятность дубликатов, но не даёт гарантии exactly-once доставки внешней платформой. При явном 429 отправка откладывается.

## Границы доступа

- Public schema: сведения о кабинете, аккаунте без токена, контакты, диалоги, сообщения, сценарии, материалы и журнал.
- RLS ограничивает чтение членством в рабочем пространстве. Запись идёт через workspace-api, который независимо проверяет Auth user, членство и допустимые поля.
- Private schema: AES-GCM токены, хешированные одноразовые OAuth states, сессии, блокировки, очередь и ключи дедупликации. Схема не включена в PostgREST. Service RPC недоступны браузерным ролям.
- OAuth state живёт 10 минут и удаляется атомарно при использовании. Токен привязан дополнительными данными шифрования к ID аккаунта.
- Операторский ответ переключает диалог в human, удаляет сессию и отменяет ранее подготовленные сообщения бота по mode_revision. Ответ напрямую из Instagram определяется через echo.
- Storage материалов публичный, чтобы ученики могли открыть PDF. Загрузка/удаление объектов ограничены пространством. Загружайте только публично выдаваемые учебные материалы.

## Развёртывание

React/Vite работает как статический SPA в Cloudflare Pages. В фронтенде нет service_role или секретов Meta. Пять Edge Functions, пять миграций и защищённое расписание лежат в supabase/. UI работает без облака через LocalRepository или с SupabaseRepository после авторизации.

Ежедневный refresh проверяет долгоживущие токены и обновляет их за 10 дней до истечения. Отключение удаляет токен. Ошибки токена помечают аккаунт для повторного входа. Номер версии Graph API — серверная переменная.

## Проверки и ограничения

- Unit/integration: 33 проверки движка, подписей, полного webhook batch, приватной очереди, удаления активного сценария, реальной PostgreSQL RLS через PGlite, CSV, пагинации и локальной сессии.
- Chromium: 11 проверок реальных пользовательских действий, сохранения после перезагрузки, защиты черновика и ширины экрана 390/768/1440.
- TypeScript + production build, Deno check всех Edge Functions.
- В CI выполняется тот же набор. Тесты не отправляют реальные сообщения.

Не проверено без внешних аккаунтов: реальный OAuth, App Review/Business Verification, production webhook, Send API, загрузка PDF в живой Storage, refresh токена, Cron/pg_net в облаке, Google Auth. PGlite проверяет PostgreSQL функции и политики приложения, но не реализует сервисы Supabase Auth/Storage/Realtime или расширения Cron.

Первая версия предназначена для одного бизнеса. Нет SaaS биллинга, AI, рассылок, автоматизации вне официального окна, галереи публикаций, вложенного PDF, HUMAN_AGENT, Live comments и встроенного удаления личных данных. Списки контактов/сценариев/материалов загружаются постранично; в кабинете доступны последние 1000 сообщений и 100 запусков. Более ранние записи остаются в базе.

## Основные каталоги

- src/pages — интерфейс и редактор сценариев.
- src/data — адаптеры локальной и облачной среды.
- shared — типы, сценарии, шаблоны, Meta events и CSV.
- supabase/migrations — таблицы, RLS и служебные SQL-функции.
- supabase/functions — авторизация, webhook, worker и API кабинета.
- supabase/setup — Cron/Vault настройка.
- tests и e2e — проверка логики, безопасности и UI.
- docs/SETUP.md — пошаговое подключение.
